## 1. Концепция и цель проекта

**AURA Music** — веб-приложение, реализующее пользовательский интерфейс стримингового музыкального сервиса. Проект создан как SPA (Single Page Application) и вдохновлён лучшими практиками таких платформ, как Spotify и Яндекс.Музыка, но реализует собственную уникальную визуальную концепцию.

### Цели проекта

- Спроектировать современный, нестандартный UI для медиаплеера
- Реализовать полноценное воспроизведение аудио через браузер
- Обеспечить удобную навигацию по разделам: главная, поиск, библиотека, страницы альбомов и артистов
- Создать систему управления треками: очередь, shuffle, repeat, избранное

### Аудитория

Молодёжь 16–30 лет, слушающая музыку в браузере — привыкшая к тёмным интерфейсам, минимализму и плавным анимациям.

## 2. Дизайн-концепция AURA

### Идея

Название **AURA** отражает визуальную метафору: мягкое свечение, ореол цвета вокруг тёмного пространства — как северное сияние над ночным городом. Интерфейс построен так, чтобы музыка воспринималась атмосферно, а не утилитарно.

### Ключевые визуальные решения

| Элемент | Решение |
|--------|---------|
| Фон | Почти чёрный (`#08080f`) с тремя анимированными градиентными пятнами — фиолетовым, голубым и розовым |
| Боковая панель | Glassmorphism: полупрозрачный фон + `backdrop-filter: blur(32px)` |
| Плеер-бар | Тот же glassmorphism, зафиксирован внизу экрана |
| Обложки | Реальные JPG-изображения; если нет — CSS-градиент как фолбэк |
| Акцентный цвет | Фиолетовый (`#7c3aed`) → голубой (`#0ea5e9`) градиент |
| Эффект «сейчас играет» | Анимированный эквалайзер из трёх полос с разным темпом |
| Карточки | Hover: подъём на 2px + светлеющий фон — ощущение «зависания» |
| Кнопка воспроизведения | Появляется только при наведении на карточку (`opacity: 0 → 1`) |

### Отличие от конкурентов

- Spotify использует единый зелёный акцент — AURA использует **градиент** (violet→cyan), каждая обложка имеет свою цветовую пару
- Яндекс.Музыка — более «тяжёлый» интерфейс; AURA делает акцент на воздухе, прозрачности, полутонах
- Aurora-пятна на фоне создают живое пространство, меняющееся при анимации

## 3. Дизайн-система

### Цветовая палитра

```
Фоны:
  --bg-base:      #08080f   (основной фон)
  --bg-surface:   #0f0f1c   (поверхности: сайдбар, плеер)
  --bg-card:      #13132a   (карточки)
  --bg-elevated:  #1a1a35   (поднятые элементы)

Акценты:
  --accent:       #7c3aed   (фиолетовый — основной)
  --accent-light: #a78bfa   (светлый фиолетовый — активные элементы)
  --sky-accent:   #0ea5e9   (голубой — вторичный)
  --rose-accent:  #f43f5e   (красный — избранное / лайки)

Текст:
  --text-primary:   #e8e8f5   (основной)
  --text-secondary: #7878a0   (вспомогательный)
  --text-muted:     #4a4a6a   (приглушённый)

Границы:
  --border-subtle: rgba(255,255,255,0.07)
```

### Типографика

- Шрифт: **Inter** (Google Fonts) — геометрическая гротеска, оптимальна для экранного чтения
- Заголовки страниц: `font-weight: 800`, размер 32–48px
- Названия треков: `font-weight: 600`, 14px
- Вспомогательный текст: `font-weight: 400`, 12px, цвет `text-secondary`

### Анимации

| Анимация | Описание |
|---------|---------|
| `float-orb` | Фоновые пятна медленно «дышат» (12–18 сек, translateX/Y + scale) |
| `fade-in-up` | Страницы появляются снизу вверх при переходе |
| Эквалайзер | 3 полосы с разными `animation-duration` (0.4 / 0.55 / 0.65s) |
| Кнопка play на карточке | `translateY(-8px) → translateY(0)` при hover |
| Hover карточек | `translateY(-2px)` + осветление фона |

### Компонентная сетка

- Сайдбар: фиксированная ширина 260px
- Плеер-бар: фиксированная высота 88px, прикреплён к низу
- Топ-бар: фиксированная высота 64px
- Контент: занимает оставшееся пространство, скроллится независимо

### Браузерные API

| API | Использование |
|-----|---------------|
| **HTMLAudioElement** | Воспроизведение MP3/WAV файлов |
| **localStorage** | Сохранение избранного между сессиями |

### Обоснование выбора

- **React** выбран как наиболее распространённая библиотека для SPA с большой экосистемой

- **Tailwind CSS** вместо CSS-модулей: позволяет описывать стили прямо в JSX без переключения между файлами
- **Zustand** вместо Redux: минималистичный (~1KB), не требует boilerplate, достаточен для задач плеера
- **TypeScript**: предотвращает ошибки типов, автодополнение в IDE, самодокументирующий код

## 5. Архитектура приложения

### Схема слоёв

```
┌─────────────────────────────────────────────┐
│                  Страницы                    │
│  HomePage  SearchPage  LibraryPage  ...      │
├─────────────────────────────────────────────┤
│              UI-компоненты                   │
│  AlbumCard  TrackRow  ArtistCard  ...        │
├─────────────────────────────────────────────┤
│           Layout-компоненты                  │
│      Sidebar   TopBar   PlayerBar            │
├─────────────────────────────────────────────┤
│           Глобальное состояние               │
│              playerStore (Zustand)           │
├─────────────────────────────────────────────┤
│         Данные и утилиты                     │
│      mockData.ts      types/index.ts         │
└─────────────────────────────────────────────┘
```

### Поток данных

```
mockData.ts  →  Страница  →  UI-компонент
                    ↕
              playerStore
                    ↕
              HTMLAudioElement  →  Браузер (звук)
```

1. Данные (треки, артисты, альбомы) хранятся в `mockData.ts` и импортируются в компоненты напрямую
2. Действия пользователя (нажать Play, лайкнуть) вызывают методы `playerStore`
3. `playerStore` управляет `HTMLAudioElement` и обновляет React-состояние
4. Компоненты подписаны на нужные части стора через `usePlayerStore(selector)`

### Маршрутизация

```
/                  →  HomePage       (главная)
/search            →  SearchPage     (поиск + жанры)
/library           →  LibraryPage    (библиотека + избранное)
/album/:id         →  AlbumPage      (страница альбома)
/artist/:id        →  ArtistPage     (страница артиста)
/playlist/:id      →  PlaylistPage   (страница плейлиста)
```

Все маршруты рендерятся внутри `Layout`, который содержит `Sidebar`, `TopBar` и `PlayerBar`. Контент страниц выводится через `<Outlet />`.

## 7. Основные функции интерфейса

### Главная страница (`/`)

- **Hero-баннер** с плейлистом недели: градиентный фон, кнопка Play появляется при наведении
- **Быстрый доступ**: сетка 4 плейлистов с цветными плашками
- **«В тренде»**: полный список треков с обложками, счётчиком прослушиваний
- **Новые релизы**: горизонтальная прокрутка карточек альбомов
- **Настроение**: 6 цветных карточек-жанров (Энергетика, Расслабление, Фокус и т.д.)
- **Плейлисты и артисты**: горизонтальные секции с карточками

### Поиск (`/search`)

- Строка поиска с автофокусом
- При пустом запросе — сетка жанров с декоративными градиентными карточками
- При вводе — живая фильтрация треков и альбомов по названию (без задержки)
- Сообщение «Ничего не найдено» при отсутствии результатов

### Библиотека (`/library`)

- **4 вкладки**: Плейлисты / Альбомы / Артисты / Любимые
- На вкладке «Любимые»: бейдж с количеством лайкнутых треков
- Пустое состояние «Любимых» с поясняющим текстом и иконкой
- Кнопка «Создать» (плейлист)

### Страница альбома / плейлиста

- Большая обложка с цветной тенью (`box-shadow` в цвет градиента)
- Цветной градиентный ореол за шапкой (частичная заливка фона)
- Кнопки: Play/Pause, лайк, меню
- Треклист с номерами, длительностью, счётчиком прослушиваний
- Секция «Ещё от артиста» с горизонтальной прокруткой

### Страница артиста

- Полноэкранный шапка-баннер с градиентом и аватаром артиста
- Затухание в основной фон снизу (`gradient-to-t`)
- «Популярные треки» — топ-5 по прослушиваниям
- «Дискография» — все альбомы артиста

## 8. Как работает аудиосистема

### Принцип

Используется нативный браузерный `HTMLAudioElement`. Единственный экземпляр (`audioEl`) создаётся при загрузке модуля вне React-рендера, что исключает пересоздание при ре-рендерах.

```
Файл аудио (MP3/WAV)
       ↓
  audioEl.src = track.audioSrc
  audioEl.play()
       ↓
  событие: timeupdate  →  обновляет progress в сторе
  событие: loadedmetadata  →  обновляет duration трека
  событие: ended  →  вызывает nextTrack() или повтор
```

### Управление воспроизведением

| Действие | Что происходит |
|---------|----------------|
| Двойной клик по треку | `playTrack(track, queue)` — устанавливает новый `src`, вызывает `play()` |
| Клик Play на карточке | То же, но с очередью из треков альбома/плейлиста |
| Клик по тому же треку | `togglePlay()` — пауза или продолжение текущего |
| Клик по прогресс-бару | `setProgress(p)` → `audioEl.currentTime = p * duration` |
| Следующий трек | Ищет индекс в очереди, берёт `(i+1) % length` |
| Предыдущий трек | Если прогресс > 5% — перемотка в начало; иначе — предыдущий в очереди |
| Shuffle | Следующий трек выбирается случайно из очереди |
| Repeat One | По событию `ended` перематывает в начало и продолжает |
| Repeat All | По событию `ended` переходит к следующему (циклически) |

### Длительность треков

`duration` в данных изначально равен `0`. При первом воспроизведении событие `loadedmetadata` обновляет `duration` в сторе из реального значения аудиофайла. Функция `formatDuration(0)` возвращает `'--:--'` до загрузки.

### Громкость

Ползунок громкости напрямую управляет `audioEl.volume` (диапазон 0–1). Кнопка-иконка переключает между `0` и `0.8`.

## 9. Система избранного

### Хранение

Массив `favorites: string[]` (ID треков) хранится в Zustand-сторе и синхронизируется с `localStorage` под ключом `aura_favorites`. При перезагрузке страницы данные восстанавливаются.

### Интерфейс

- Иконка ♥ на каждой строке трека появляется при наведении
- Если трек в избранном — ♥ всегда видно, закрашено красным (`fill-current text-rose-400`)
- ♥ в плеер-баре для текущего трека
- Вкладка **«Любимые»** в библиотеке показывает все лайкнутые треки

### Логика

```typescript
toggleFavorite(trackId) {
  favorites = favorites.includes(id)
    ? favorites.filter(x => x !== id)   // убрать
    : [...favorites, id]                 // добавить
  localStorage.setItem('aura_favorites', JSON.stringify(favorites))
}
```

## 10. Добавление новых треков

Система поддерживает расширение каталога без изменения кода компонентов.

### Шаги

1. Положить аудиофайл в `public/audio/` (MP3 или WAV)
2. Положить обложку в `public/covers/` (JPG или PNG)
3. В файле `src/data/mockData.ts` добавить:
   - Объект `Artist` в массив `artists` (если новый артист)
   - Объект `Album` в массив `albums`
   - Объект `Track` в массив `tracks` с полями `audioSrc` и `coverSrc`
   - ID трека в нужные плейлисты (`trackIds`)

### Пример

```typescript
// Новый артист
{ id: 'a3', name: 'Miyagi', bio: 'Российский хип-хоп', gradient: ['#14b8a6', '#6366f1'], monthlyListeners: 8_500_000, verified: true }

// Новый альбом
{ id: 'al3', title: 'Космос', artistId: 'a3', year: 2024, gradient: ['#14b8a6', '#6366f1'], type: 'album' }

// Новый трек
{
  id: 't3',
  title: 'Kosmos',
  albumId: 'al3',
  artistId: 'a3',
  duration: 0,                         // обновится автоматически из файла
  plays: 12_000_000,
  audioSrc: '/audio/miyagi-kosmos.mp3',
  coverSrc: '/covers/miyagi-kosmos.jpg',
}
```

### Соглашение об именах файлов

Допускаются любые имена — `audioSrc` и `coverSrc` задаются явно в данных, автоматического связывания по имени нет. Это даёт полную свободу в именовании файлов.

## 11. Запуск и деплой

### Локальная разработка

```bash
npm install      # установка зависимостей
npm run dev      # запуск dev-сервера (http://localhost:5173)
```

### Сборка

```bash
npm run build    # TypeScript-компиляция + Vite-сборка → папка dist/
npm run preview  # предпросмотр production-сборки локально
```

### Деплой на Vercel

Проект настроен для автоматического деплоя с GitHub:

1. Подключить репозиторий на [vercel.com](https://vercel.com)
2. Framework Preset: **Vite**
3. Build Command: `npm run build`
4. Output Directory: `dist`

Файл `vercel.json` обеспечивает корректную работу клиентского роутера:

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

Без этого правила прямые переходы по URL (например, `/album/al1`) возвращали бы 404.
